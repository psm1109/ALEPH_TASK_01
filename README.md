# 나를 설명하는 작은 기록

저를 처음 만나는 분들에게 제가 어떤 사람이고, 무엇을 좋아하며, 어떤 경험을 해왔는지 보여주는 개인 소개 페이지입니다.

> 저는 이론에 머무르기보다 실제 경험을 통해 깊이 배우고 싶은 사람입니다.

[공개 페이지 보기](https://aleph-task-t01.vercel.app/)

## 페이지 구성

- **소개**: 페이지의 대상과 목적, 나를 설명하는 문장을 번갈아 보여줍니다.
- **공개 범위 점검표**: 공개하는 정보와 공개하지 않는 정보를 안내합니다.
- **강점과 취향 세 가지**: 배움을 적용하는 실천력, 신뢰를 만드는 협업 방식, 노래·기타와 여행·등산에 대한 관심을 소개합니다. 각 경험은 요약과 상황·행동·결과로 구성되어 있습니다.
- **저를 움직이는 세 가지 가치**: 건강·자유·신뢰가 나에게 갖는 의미를 설명합니다.
- **저를 이해하는 몇 가지 기준**: 몰입하는 순간, 힘이 빠지는 순간, 사람들과 가까워지는 방식, 알아두면 좋은 점을 담았습니다.
- **나만 보는 자리**: 공개 소개가 끝나는 지점에 분명한 경계를 두고, 패스키 인증 뒤에만 Neon의 비공개 기록을 보여줍니다.

카드 5의 계정 격리 변경은 운영 커밋 `9839146`에 배포됐습니다. 기존 패스키와 자료는 내부 `owner` 계정에 남습니다. 운영 Neon에 `db/migrations/20260928_add_passkey_account_isolation.sql`이 적용됐고 두 계정의 양방향 교차 요청 거절을 확인했습니다. 현재 작업 트리에서는 잠긴 화면에서 `testA`·`testB` 같은 사이트 사용자 ID로 새 패스키 계정을 등록하도록 변경했으며, 이 추가 변경은 아직 운영 DB·배포에서 확인하지 않았습니다. 남은 확인 항목과 가린 요청·응답은 `docs/card5/README.md`에 기록합니다.

| 경험 상세 보기 | 각 카드의 ‘상황·행동·결과 자세히 보기’를 눌러 펼치거나 접습니다. |

| 비공개 기록 | ‘패스키로 열기’를 누르면 등록 여부를 확인합니다. 등록된 패스키가 없으면 같은 페이지에서 일회용 소유자 코드를 확인한 직후 Windows의 패스키 등록 창을 열고, 있으면 바로 인증한 뒤 Neon 자료를 불러옵니다. |
| 첫 패스키 설정 | 기본 흐름은 잠금 화면에서 바로 시작합니다. `/setup`은 직접 접근이 필요한 경우를 위한 예비 설정 경로입니다. 소유자 확인 뒤 Windows Hello·휴대폰·패스키 관리자 중 브라우저가 제공하는 저장 위치를 선택합니다. |
| 패스키 추가 | 이미 패스키로 인증한 상태에서만 비공개 공간의 ‘패스키 추가’를 사용할 수 있습니다. |
| 패스키 관리 | 인증 뒤 등록된 패스키의 추정 저장 방식과 추가·최근 사용 시각을 확인하고 불필요한 패스키를 삭제합니다. 계정 잠금을 막기 위해 마지막 패스키는 삭제할 수 없습니다. |
| 잠그기 | `HttpOnly` 인증 세션을 만료시키고 화면의 비공개 DOM을 즉시 비웁니다. |
| 맨 위로 이동 | 페이지 하단의 ‘맨 위로’ 링크를 사용합니다. |

## 접근성 및 화면 대응

- 제목을 `h1`, `h2`, `h3` 단계로 구성했습니다.
- ‘본문으로 건너뛰기’ 링크와 키보드 초점 표시를 제공합니다.
- 버튼은 Enter·Space로 실행할 수 있으며, 학습 모달 안에서는 Tab·Shift+Tab으로 버튼 사이를 이동합니다.
- 시스템의 ‘움직임 줄이기’ 설정에 대응합니다.
- 화면 너비에 따라 카드와 공개 범위 영역의 배치를 조정합니다.

접근성 기능의 구현 여부와 최종 배포 화면의 검사 결과는 구분합니다. 제출 전에는 실제 공개 페이지에서 두 기준 해상도(1366×768, 1920×1080), 텍스트 대비, 키보드 조작, 링크와 콘솔 오류를 확인합니다.

## 실행 방법

Node.js 22 이상에서 의존성을 설치하고 Vite 개발 서버를 실행합니다.

```powershell
npm install
npm run dev
```

API까지 로컬에서 확인하려면 Vercel CLI로 실행하고 `.env.local`에 아래 환경변수를 설정해야 합니다. 비밀값 원문은 Git에 추가하지 않습니다.

```text
DATABASE_URL
PASSKEY_RP_ID
PASSKEY_ORIGIN
PASSKEY_OWNER_NAME
PASSKEY_USER_HANDLE
PASSKEY_SETUP_SECRET
SESSION_SECRET
CBOR_NATIVE_ACCELERATION_DISABLED=true
```

`PASSKEY_SETUP_SECRET`와 `SESSION_SECRET`은 서로 다른 32자 이상의 무작위 값이어야 합니다. `PASSKEY_RP_ID`는 스킴 없는 배포 호스트, `PASSKEY_ORIGIN`은 `https://`를 포함한 정확한 배포 Origin으로 설정합니다. 예시 형식은 `.env.example`에서 확인할 수 있습니다.

`SESSION_SECRET`이 없거나 32자 미만이면 등록·인증 옵션 API가 `503`을 반환하며 WebAuthn ceremony를 시작하지 않습니다. 모바일에 패스키를 만든 뒤 세션 발급만 실패하는 불완전한 등록을 막기 위한 사전 검사이므로, 반드시 첫 등록 전에 설정하고 재배포해야 합니다.

Neon SQL Editor에서 `db/schema.sql`을 먼저 실행합니다. 이 SQL은 사람이 구분할 수 있는 이름이 붙은 패스키 자격 증명, 5분짜리 일회용 챌린지, 폐기 가능한 로그인 세션, 패스키 전용 `passkey_private_items` 테이블을 만들고 세 종류의 가상 자리표시자를 넣습니다. 기존 배포에는 `db/migrations/20260928_add_passkey_display_name.sql`, `db/migrations/20260928_restore_revocable_passkey_sessions.sql`, `db/migrations/20260928_add_passkey_account_isolation.sql`, `db/migrations/20260928_add_site_user_ids.sql`을 순서대로 해당 코드 배포 전에 적용합니다. 마지막 마이그레이션은 기존 내부 계정과 자료를 보존하며 표시용 ID를 추가합니다. 세션 마이그레이션은 legacy 테이블 제거 파일보다 나중에 실행되도록 이름을 정했습니다. 과제 검증 자료에는 실제 개인정보 대신 만들어 넣은 내용만 사용합니다. 기존 `private_items`는 별도 자료 테이블이므로 읽거나 수정하지 않습니다.

```powershell
npm test
```

이 명령은 프로덕션 빌드, 비인증 `401`, 등록 권한 `403`, 최초 설정 코드 재사용 `409`, 추가·관리 기능의 인증 세션 요구, 로그아웃 세션 재사용 차단, 다른 기기 세션 유지, 마지막 패스키 삭제 차단, 응답 캐시 금지, 공개 빌드 내 비공개 문구 부재를 검사합니다.

```text
ALEPH_TASK_01/
├── index.html       # 페이지 내용과 구조
├── styles.css       # 스타일, 반응형 배치, 애니메이션
├── script.js        # 기존 상호작용과 패스키 브라우저 흐름
├── api/             # Vercel 서버리스 패스키·비공개 자료 API
├── db/schema.sql    # Neon 테이블과 초기 비공개 항목 자리표시자
├── docs/card1/      # 화면과 비인증 응답 증거
├── tests/           # 인증 경계 회귀 검사
├── images/
│   ├── 1.jpg
│   ├── 2.jpg
│   ├── 3.jpg
│   ├── 4.jpg
│   ├── 5.jpg
│   └── 6.jpg
├── vercel.json
└── README.md
```

Vercel은 `npm run build`로 `dist/`를 만들고 `api/`를 Node.js 함수(Node 22 이상)로 배포합니다. 환경변수를 설정한 뒤 최초 1회 `https://배포도메인/setup`에서 일회용 설정 코드로 소유자를 확인하고 패스키를 등록합니다. 이때 개인키는 Neon이나 Vercel이 아니라 Windows Hello, 휴대폰 또는 사용자가 선택한 패스키 관리자에 생성됩니다. 서버에는 공개키와 검증용 메타데이터만 저장됩니다.

첫 credential이 저장되면 `/setup`의 설정 코드 등록은 서버에서 자동으로 `409` 거절됩니다. 등록과 로그인을 확인한 뒤에는 방어를 겹치기 위해 Vercel의 `PASSKEY_SETUP_SECRET`도 제거합니다. 추가 패스키는 기존 패스키로 비공개 공간을 연 상태에서만 등록할 수 있습니다. 모든 패스키를 잃어버렸다면 현재 구현에는 자동 복구 경로가 없으므로, credential 정리와 부트스트랩 복구는 운영자가 Neon/Vercel에서 명시적으로 수행해야 합니다.

## 비공개 경계 보안

- 인증 쿠키는 JavaScript가 읽을 수 없는 `HttpOnly`, HTTPS 전용 `Secure`, 교차 사이트 전송을 막는 `SameSite=Strict`로 발급합니다.
- 로그인마다 임의 세션 ID를 발급하고 Neon에는 SHA-256 해시와 만료 시각만 저장합니다. 로그아웃은 현재 세션 행만 삭제하므로 같은 쿠키를 다시 보내도 거절되며 다른 기기 세션은 유지됩니다.
- 등록·인증 챌린지는 Neon에 저장하고 5분 이내 한 번만 소비합니다.
- 브라우저에서 등록·인증을 취소하면 해당 일회용 챌린지를 즉시 폐기하고, 등록 취소 시 credential이 저장되지 않았다는 안내를 표시합니다.
- 사용자 검증을 `required`로 두고 등록된 credential의 서명과 카운터를 SimpleWebAuthn 서버에서 검증합니다.
- discoverable credential을 `required`로 생성하고 authenticator 종류를 강제하지 않아 Windows Hello, 휴대폰·QR, 동기화 패스키 관리자, FIDO2 보안 키를 브라우저가 제시할 수 있습니다.
- 최초 설정 코드는 첫 credential이 생기기 전 `/setup`에서만 사용할 수 있으며, 이후에는 등록 옵션과 검증 단계 모두 `409`로 차단됩니다.
- 패스키 목록 조회와 삭제는 인증 세션에서만 허용하며, DB 트랜잭션에서 최소 한 개의 credential이 남도록 강제합니다.
- `/api/private-items`는 세션을 먼저 검사하고, 인증되지 않으면 DB를 읽지 않은 채 `401`을 반환합니다.
- 비공개 자료 응답과 인증 API에는 `Cache-Control: no-store`를 적용합니다.
- 공개 HTML과 번들에는 비공개 항목 제목·본문을 넣지 않습니다. 인증 성공 뒤 API 응답을 `textContent`로 렌더링합니다.

정적 검사 통과는 실제 Neon 스키마 적용, Vercel 환경변수 설정, Windows Hello·Touch ID 등 실기기 패스키 성공을 뜻하지 않습니다. 운영 검증 시에는 등록 → 로그아웃 → 패스키 로그인 → 직접 API 차단을 순서대로 확인해야 합니다.

## 페이지에 선언한 공개 범위

**공개하는 정보**

- 강점과 취향 및 관심사
- 저를 움직이는 가치
- 저를 이해하는 몇 가지 기준

**공개하지 않는 정보**

- 실명, 개인 연락처, 상세 거주 위치
- 학교·기관 식별 정보와 개인 계정
- 인증에 쓰이는 정보와 사적인 대화 내용

이 목록은 페이지에 명시한 공개 원칙입니다. 공개 여부를 확인할 때는 본문뿐 아니라 학습 이미지와 연결된 외부 자료도 함께 검토합니다.
