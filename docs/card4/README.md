# Card 4 — 복수 패스키와 삭제 후 복구 검증 기록

검증일은 2026-09-28(Asia/Seoul)이며, 운영 주소는 `https://aleph-task-t01.vercel.app`입니다. 운영 Chrome에서 직접 확인한 사실과 코드·회귀 검사 결과를 구분합니다. credential ID, challenge, ceremony ID, 세션 쿠키와 토큰 원문은 기록하지 않았습니다.

| 기준 | 결과 | 제출 기록(민감 값 가림) |

## 운영 검증 순서

```text
1. 삭제 전 목록
내 휴대폰
- 위치: 이 기기의 Windows Hello 또는 기기 잠금
- 추가: 2026-09-28 00:30
- 최근 사용: 사용 기록 없음

구글 계정 패스키
- 위치: 휴대폰 또는 동기화된 패스키 관리자
- 추가: 2026-09-28 08:53
- 최근 사용: 2026-09-28 15:56

2. 삭제
대상: 내 휴대폰
화면 결과: 패스키를 삭제했습니다.

3. 삭제 후 목록
남은 패스키: 구글 계정 패스키
삭제 버튼: 비활성화
도움말: 마지막 패스키는 삭제할 수 없습니다.

4. 남은 패스키 로그인
대상: 구글 계정 패스키
결과: 성공
화면: 패스키 인증됨, 비공개 기록 반환

5. 삭제한 패스키 재시도
대상: 삭제했던 이 기기/Windows Hello 패스키
결과: 인증 선택 목록에 나타나지 않아 선택·로그인 불가
취소 뒤 화면: 비공개 기록 잠김
안내: 패스키 인증을 취소했거나 인증 창을 완료하지 않았습니다.
```

## 0개 방지 동작

- 화면은 패스키가 하나만 남으면 삭제 버튼을 비활성화하고 이유를 표시합니다.
- 서버는 화면 우회를 가정해 삭제 시 전체 credential 행을 잠근 뒤, 개수가 1보다 클 때만 삭제합니다.
- 마지막 패스키 삭제 요청은 `409`로 거절되므로 계정이 패스키 0개 상태에 빠지지 않습니다.
- credential ID, 쿠키, 세션·토큰, challenge 원문은 이 기록에 포함하지 않았습니다.

## 증거 보존 상태

- 두 패스키가 보이는 삭제 전 목록과 하나가 남은 삭제 후 목록은 운영 브라우저에서 캡처해 검증했습니다.
- 현재 저장소에는 브라우저 캡처 이미지 파일을 저장하지 못했으며, 위 표와 실행 기록에 화면의 표시값을 그대로 옮겼습니다.
